🐳 ជំហាន ១: Dockerfile Setup

Create file Dockerfile នៅ root project:

FROM php:8.2-apache

RUN docker-php-ext-install pdo pdo_mysql mysqli
RUN a2enmod rewrite && \
    sed -i 's|AllowOverride None|AllowOverride All|g' /etc/apache2/apache2.conf

RUN echo 'output_buffering = On' > /usr/local/etc/php/conf.d/custom.ini

COPY . /var/www/html/

RUN chown -R www-data:www-data /var/www/html \
    && chmod -R 755 /var/www/html

RUN echo "ServerName localhost" >> /etc/apache2/apache2.conf

EXPOSE 80
⚠️ សំខាន់: DocumentRoot ត្រូវ point ទៅ project root (/var/www/html/) មិនមែន /public ទេ — ព្រោះ app/ folder ស្ថិតនៅខាងក្រៅ public/

⚙️ ជំហាន ២: .htaccess Setup

File .htaccess នៅ root project:

php_value upload_max_filesize 200M
php_value post_max_size       250M
php_value max_execution_time  300
php_value max_input_time      300
php_value memory_limit        256M

Options -Indexes
DirectoryIndex public/index.php index.php index.html
Require all granted
✅ DirectoryIndex public/index.php — ធ្វើឱ្យ root URL បើក login page ដោយស្វ័យប្រវត្តិ

🗄️ ជំហាន ៣: Clever Cloud MySQL

Setup:

  1. ចូល console.clever-cloud.com
  2. Create addon → MySQL → Dev plan (Free)
  3. Copy credentials: HOST, DATABASE, USER, PASSWORD
  4. Import SQL schema ពី phpMyAdmin

config/db_config.php:

<?php
$host     = "xxxx-mysql.services.clever-cloud.com";
$dbname   = "your_dbname";
$username = "your_username";
$password = "your_password";

if (!defined('BASE_URL')) {
    define('BASE_URL', 'https://your-app.onrender.com/');
}

try {
    $conn = new PDO("mysql:host=$host;dbname=$dbname;charset=utf8", $username, $password);
    $conn->setAttribute(PDO::ATTR_ERRMODE, PDO::ERRMODE_EXCEPTION);
} catch(PDOException $e) {
    die("Connection failed: " . $e->getMessage());
}

// DB Sessions — survive Render server restarts
if (session_status() === PHP_SESSION_NONE) {
    require_once __DIR__ . '/session_handler.php';
    lc_init_db_sessions($conn);
}
?>

📧 ជំហាន ៥: Brevo Email Setup

⚠️ ហេតុអ្វី Brevo? Render free tier block outbound SMTP (port 587) ទាំងស្រុង — Brevo ប្រើ HTTPS API (port 443) ដែលមិន block!

Setup Brevo:

  1. ចូល brevo.com → Sign up with Google
  2. Fill profile → Free plan (300 emails/day)
  3. Settings ⚙️ → SMTP & API → Generate API Key → Copy

Setup Brevo Sender Email:

  1. Brevo Dashboard → Settings ⚙️ → Senders, domains, IPs
  2. ចុច Add a sender → Email: your@gmail.com → Name: Social7
  3. ចូល Gmail → ចុច verify link ដែល Brevo បញ្ជូន → Verified ✅
⚠️ សំខាន់: SMTP_FROM_EMAIL ត្រូវតែជា email ដែល Verified ក្នុង Brevo — បើប្រើ onboarding@resend.dev Gmail នឹង block email!

Add Environment Variables ក្នុង Render:

KeyValue
BREVO_API_KEYxkeysib-xxxxxxxxxxxx (ពី Brevo Settings → SMTP & API)
SMTP_FROM_EMAILyour@gmail.com (Verified sender ក្នុង Brevo)
SMTP_FROM_NAMESocial7
✅ Free tier: 300 emails/ថ្ងៃ — គ្រប់គ្រាន់សម្រាប់ social network តូច

របៀប Verify Email ដំណើរការ:

  1. User Sign up → account created ជាមួយ status Pending
  2. Brevo send email "Verify your Social7 account" → user inbox

🔐 ជំហាន ៦: Database Sessions (Fix Render Logout Bug)

⚠️ បញ្ហា: Render free tier spin down server រៀងរាល់ 15 នាទី inactive → session files បាត់ → user logout ដោយស្វ័យប្រវត្តិ → "Access denied"

Fix: Store PHP sessions ក្នុង MySQL database ជំនួស server files

Files ដែលត្រូវ Create/Edit:

FileAction
config/session_handler.phpCreate — DbSessionHandler class
config/db_config.phpEdit — Add lc_init_db_sessions($conn)

session_handler.php logic:

  • Implement SessionHandlerInterface (open, close, read, write, destroy, gc)
  • Store sessions ក្នុង table php_sessions (auto-create)
  • Sessions expire after 24 hours

db_config.php — Add before session_start():

if (session_status() === PHP_SESSION_NONE) {
    require_once __DIR__ . '/session_handler.php';
    lc_init_db_sessions($conn);
}
✅ Sessions persist 24 ម៉ោង — Render restart ក៏ login នៅដដែល!

🔑 ជំហាន ៨: Google & Facebook Login Setup

⚠️ បញ្ហា: .env ស្ថិតក្នុង .gitignore → មិន upload ទៅ Render → credentials ទទេ → Google/Facebook login fail!

Fix: Add ទៅ Render Environment Variables

KeyValue (ពីណា)
GOOGLE_CLIENT_IDGoogle Cloud Console → Credentials
GOOGLE_CLIENT_SECRETGoogle Cloud Console → Credentials
FACEBOOK_APP_IDMeta for Developers → App Settings
FACEBOOK_APP_SECRETMeta for Developers → App Settings
FACEBOOK_REDIRECT_URIhttps://your-app.onrender.com/app/Controllers/Auth/facebook_auth.php

Google Cloud Console — Update Redirect URI:

  1. ចូល console.cloud.google.com
  2. APIs & Services → Credentials
  3. ចុច OAuth 2.0 Client ID
  4. Authorized redirect URIs → Add: 
    https://your-app.onrender.com/app/Controllers/Auth/google_auth.php
  5. Save

Facebook Developer Console — Update Redirect URI:

  1. ចូល developers.facebook.com
  2. App → Facebook Login → Settings
  3. Valid OAuth Redirect URIs → Add: 
    https://your-app.onrender.com/app/Controllers/Auth/facebook_auth.php
  4. Save Changes

Fix env.php — Read from Render env vars:

// Fall back to Render environment variables
if (isset($vars[$key])) return $vars[$key];
$sys = getenv($key);
if ($sys !== false && $sys !== '') return trim($sys);
return $_ENV[$key] ?? ($_SERVER[$key] ?? $default);
✅ env() reads .env file locally + Render environment variables on server

🐛 ជំហាន ១៤: Bug Fixes — Post Display

Fix 1: Post timestamps show wrong time (7h ago)

មូលហេតុ: Server stores UTC time, JavaScript interprets as local time (UTC+7)

Fix: Add Z suffix to dates in PostController fetch action:

$post['CreatedAt'] = str_replace(' ', 'T', $post['CreatedAt']) . 'Z';
✅ Posts now show correct "Just now", "5m ago", etc.

Fix 2: Images show "Post media" (broken) after server restart

មូលហេតុ: safeMediaPath() function ប្រើ basename() ដែល strip Cloudinary URL ទៅជា filename ប៉ុណ្ណោះ

Fix: Check if URL starts with https:// before processing:

if (str_starts_with($mediaPath, 'https://') || str_starts_with($mediaPath, 'http://')) {
    return $mediaPath; // Cloudinary URL — return unchanged
}

Fix 3: Default avatar 404

Fix: Update resolveAvatarUrl() in dashboard.js:

if (raw === 'default.png' || raw === 'default-avatar.svg') return FALLBACK_AVATAR;

Fix 4: favicon.ico 404

Fix: Create public/img/favicon.svg → add link tag in dashboard_shell.php

💬 ជំហាន ១៥: Messages Page + Session Fix

Messages redirect to login — Session inconsistency

⚠️ Root cause: Login uses FILE sessions, but message.php loaded db_config FIRST → used DB sessions → empty session → redirect to login!

Fix message.php: Load session_start() BEFORE db_config (consistent with login):

if (session_status() === PHP_SESSION_NONE) session_start();
require_once __DIR__ . "/../../../config/db_config.php";
✅ Messages page now uses same file session as login → stays logged in!

Google avatar double URL in Messages

មូលហេតុ: message.js prepends imagePath prefix to Google OAuth URLs (already full https://)

Fix in message.js:

// Before (wrong):
`${window.APP_CONFIG.imagePath}${friend.ProfilePic}`

// After (correct):
friend.ProfilePic.startsWith('http') ? friend.ProfilePic
    : `${window.APP_CONFIG.imagePath}${friend.ProfilePic}`
✅ Google login user avatars now display correctly in Messages!
